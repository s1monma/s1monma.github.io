# Crypto Terms Glossary

Static website for the Keystone Crypto Collective glossary. Editors update a
shared Excel file; a Python script converts it to JSON; a static site reads
that JSON and renders search, filters, and cross-linked term pages entirely
in the browser.

## How it fits together

```
Team edits Excel (on OneDrive / SharePoint)
                │
                ▼
       python3 sync.py            ← Someone on the team runs this after edits
                │
                ▼
        site/data.json             ← The generated JSON snapshot
                │
                ▼
  Commit + push to GitHub          ← (or copy site/ to whatever host you pick)
                │
                ▼
     Hosting redeploys, users see the update in their browser
```

Nothing in the site talks to a database. Everything the browser needs lives
in `site/data.json`, which the sync script rewrites each time it runs.

## Folder layout

```
glossary-site/
├── sync.py                    ← Excel → JSON converter
├── README.md                  ← this file
└── site/                      ← the static website (this is what gets hosted)
    ├── index.html
    ├── styles.css
    ├── app.js
    └── data.json              ← generated by sync.py; do not edit by hand
```

## One-time setup (any editor's laptop)

1. Install Python 3 (macOS ships with it; on Windows, install from python.org).
2. Install the one Python dependency:
   ```bash
   pip3 install openpyxl
   ```
3. Make sure the source Excel file is available. Two workable setups:
   - **OneDrive desktop sync** (recommended): open OneDrive on your laptop and
     make sure the file `KS Crypto Collective - Crypto Terms Glossary - <date>.xlsx`
     is set to "Always keep on this device." Then edit `EXCEL_PATH` at the top
     of `sync.py` to point at the local synced copy.
   - **Manual copy**: download a fresh copy of the Excel into this folder each
     time you want to update, and pass the path as an argument (see below).

## Publishing an update

After the team has finished editing the Excel:

```bash
cd glossary-site
python3 sync.py                            # uses the default path from sync.py
# or
python3 sync.py "/path/to/latest.xlsx"     # override the source file
```

Expected output:
```
Reading .../KS Crypto Collective - Crypto Terms Glossary - <date>.xlsx
Wrote .../glossary-site/site/data.json
  terms: 38  with_citations: 38  litigation: 7
```

Then, once hosting is set up:
```bash
git add site/data.json
git commit -m "sync glossary from Excel"
git push
```

GitHub Pages (or whichever host we use) will redeploy automatically.

## Testing changes locally

Browsers block `fetch("data.json")` when a page is opened via `file://`, so run
a tiny local server from the `site/` folder:

```bash
cd site
python3 -m http.server 8000
```

Open http://localhost:8000 in your browser.

## Excel schema

The sync script expects a sheet named `glossary` with:

- Row 1: empty
- Row 2: header row (`Term`, `Definition`, `Example`, `Additional Context`,
  `Child Term?`, `Source`, `Citation`, `Litigation Example`, `Links`)
- Row 3 onward: one term per row

Column layout (1-indexed):

| Col | Field              | Notes |
|-----|--------------------|-------|
| A   | Row number         | 1, 2, 3, … |
| B   | Reference          | e.g. `[4]` |
| C   | Term               | Required — a row without a term is skipped |
| D   | Definition         | Optional — some terms are citation-only |
| E   | Example            | Optional |
| F   | Additional Context | Optional |
| G   | Child Term?        | Comma-separated list of related term names |
| H   | Source             | e.g. "Keystone White Paper" |
| I   | Citation           | Full citation, may include a URL |
| J   | Litigation Example | Optional; `[Case Name]: description…` format |
| K   | Links              | Optional |

If you rename or reorder columns in the Excel, update `COLS` at the top of
`sync.py` to match.

## What the frontend does

- Loads `data.json` once and holds all 38 terms in memory.
- Alphabetical index in the left rail with letter jump-bar.
- Full-text search across term / definition / example / context.
- Filter chips: "All terms" / "Has citation" / "Has litigation".
- Term detail in the middle with Definition, Example, Additional Context,
  Citation (pull-quote with linked URL), Litigation Example, Links sections.
- "Mentioned in this entry" in the right rail — combines the spreadsheet's
  Child Term? list with reverse-lookups (terms that point back at this one)
  and text-based auto-linking (whenever another term's name appears in this
  term's definition/example/context).

## Syncing data from SharePoint (Microsoft Graph API)

The sync script connects to SharePoint via **Microsoft Graph API** using an Azure AD (Microsoft Entra ID) application with Application permissions. Each run downloads the latest Excel spreadsheet and regenerates `site/data.json` and `site/data.js`.

### 1. Azure AD App Registration (One-time IT Setup)

Ask your IT / Azure administrator to perform the following:

1. In the **Microsoft Entra admin center** (Azure Portal > Microsoft Entra ID > App registrations), select **New registration**.
2. **Name**: `Keystone Glossary Sync` (or similar).
3. **Supported account types**: `Accounts in this organizational directory only (Single tenant)`.
4. Under **Certificates & secrets** > **Client secrets**, create a new secret and note the **Value** (`AZURE_CLIENT_SECRET`).
5. Under **API permissions**, select **Add a permission** > **Microsoft Graph** > **Application permissions**, and add:
   - `Files.Read.All` (or `Sites.Read.All`)
6. Click **Grant admin consent for <Your Organization>**.
7. Note down:
   - **Application (client) ID** (`AZURE_CLIENT_ID`)
   - **Directory (tenant) ID** (`AZURE_TENANT_ID`)

### 2. Configure Environment

Copy `.env.example` to `.env` in the `glossary-site` folder:

```bash
cp .env.example .env
```

Set the credentials and SharePoint location in `.env`:

```ini
AZURE_TENANT_ID=00000000-0000-0000-0000-000000000000
AZURE_CLIENT_ID=11111111-1111-1111-1111-111111111111
AZURE_CLIENT_SECRET=your_secret_value_here
SHAREPOINT_SITE_URL=https://yourcompany.sharepoint.com/sites/AICollective
SHAREPOINT_FILE_PATH=Shared Documents/KS Crypto Collective - Crypto Terms Glossary.xlsx
```

Test your authentication:
```bash
python sync.py --test-auth
```

### 3. Running the Sync

To download the latest Excel from SharePoint and update the site:

```bash
python sync.py
```

Expected output:
```
[Graph API Mode] Authenticating to Microsoft Graph API...
[Graph API] Resolving SharePoint site: https://yourcompany.sharepoint.com/sites/AICollective
[Graph API] Requesting file download from Microsoft Graph...
[Graph API] Successfully downloaded Excel file (48.2 KB) -> sharepoint_glossary.xlsx
Reading sheet 'glossary' from sharepoint_glossary.xlsx
Preserved research papers & cluster tags for 52 existing terms.

[Sync Complete]
  Wrote: site/data.json
  Wrote: site/data.js
  Summary: 52 terms | 52 citations | 32 papers | 10 litigation examples
```

### Local Fallback (Offline / Manual File)

You can also run against a local Excel file without Azure AD credentials:

```bash
python sync.py --local "path/to/glossary.xlsx"
```

## Automated Sync with GitHub Actions (Optional)

You can run `sync.py` on a schedule (e.g., nightly) using GitHub Actions:

```yaml
name: Nightly Glossary Sync
on:
  schedule:
    - cron: '0 4 * * *'  # 4am UTC daily
  workflow_dispatch:

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install openpyxl
      - run: python sync.py
        env:
          AZURE_TENANT_ID: ${{ secrets.AZURE_TENANT_ID }}
          AZURE_CLIENT_ID: ${{ secrets.AZURE_CLIENT_ID }}
          AZURE_CLIENT_SECRET: ${{ secrets.AZURE_CLIENT_SECRET }}
          SHAREPOINT_SITE_URL: ${{ secrets.SHAREPOINT_SITE_URL }}
          SHAREPOINT_FILE_PATH: ${{ secrets.SHAREPOINT_FILE_PATH }}
      - uses: stefanzweifel/git-auto-commit-action@v5
        with:
          commit_message: "Automated glossary sync from SharePoint"
          file_pattern: "site/data.json site/data.js"
```
